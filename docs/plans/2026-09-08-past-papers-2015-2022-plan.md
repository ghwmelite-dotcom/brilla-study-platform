## 2. Phase plan

Ordering rationale: **recency matters most to students** (2019–2022 papers reflect the current syllabus and question style; 2015–2018 are nice-to-have depth), and **core subjects have the largest audience** (every WASSCE candidate sits Core Math, English, Int. Science, Social Studies; every BECE candidate sits the same 8).

| Phase | Scope | Papers | ~Questions | Size |
|---|---|---|---|---|
| **1** | 4 core WASSCE subjects × 2019–2022, Paper 1 | 16 | ~800 | M (content) |
| **2** | BECE 8 subjects × 2019–2022, Paper 1 | 32 | ~1,600 | L (content) |
| **3** | Remaining ~12 WASSCE subjects × 2019–2022, Paper 1 | ~48 | ~2,400 | L (content) |
| **4** | 2015–2018 backfill, all subjects above (BECE + WASSCE Paper 1) | ~96 | ~4,800 | XL — split into yearly sub-drops (2022→2015 order already covered; do 2018→2015) |
| **5** | Paper 2 theory expansion (4 core subjects, all shipped years; extend 2023 baseline) | 20–32 | per-question long-form | L — separate authoring track |

Each phase gates the next: do not start Phase N+1 authoring until Phase N has passed review and shipped to prod. Phase 5 can run in parallel from Phase 3 onward (different authoring skill set — structured essay/theory questions, per `generate-wassce-paper2-theory-bank.mjs` precedent).

**Phase 1 totals: 16 papers, ~800 questions.**

## 3. Tooling work (build once, reuse every phase)

**Build `scripts/generate-past-paper-bank.mjs`** — the one new engineering piece. Modelled on the existing `generate-*-bank.mjs` generators (e.g. `generate-wassce-foundation-beta-bank.mjs`) with three differences:

1. Emits a `past_papers` row **plus** linked `questions` rows with `past_paper_id` set, keyed by `year` / `month` / paper series (May/June WASSCE, BECE sitting month).
2. SQL shape template: the folded 2023/2024 migrations (028, 035–039, 056–061 in `database/schema.sql`) are the reference INSERT shape — copy that, not a new schema.
3. Output lands as `content/batches/*.json` + numbered migration, run through `scripts/validate-question-batch.mjs` and the shared `scripts/question-content-lib.mjs` validation (provenance fields, release rows, difficulty/explanation checks).

**Migration numbering:** past-paper migrations start at **402+** (370–371 platform fixes; 372–379 reserved for the school-subscription workstream; 380–386 flashcards batch 1; 387–401 NSMQ expansion batch 1). Allocate per phase batch as needed, re-verifying `database/migrations/` before each generation.

**Required gates per batch (existing machinery, no new infra):**
- Contract/parity test: generated JSON ↔ generated SQL must agree on counts and IDs (pattern from existing bank generators' parity tests).
- Fresh-bootstrap gate: `scripts/verify-fresh-bootstrap.cjs` must pass with the new migrations folded-check intact.
- `question_content_releases` rows with `official_exam_board_content = 0` for every question (hard content policy).

## 4. Content production approach

AI-assisted authoring with academic review gates, per the governance playbook — same pipeline that produced the 2023/2024 banks and beta expansions.

**Per-paper acceptance criteria (reviewer checklist):**
- Question count matches the year's paper format (~50 for Paper 1; per `total_questions` on the `past_papers` row).
- Topic spread covers the subject's topic list proportionally (join against the subject's topics; no topic with 0 questions unless the blueprint excludes it).
- Difficulty mix across easy/medium/hard consistent with existing banks (target the same distribution the validator enforces).
- 100% explanation coverage — every question carries an explanation.
- Duplicate-prompt check against ALL existing batches (validator's cross-batch dedupe), not just within the new paper.
- Provenance block + "not official WAEC material" label on the batch manifest.

## 5. Honesty note — what "year" means for original content

**Hard rule (unchanged):** official WAEC documents are curriculum blueprints only. A "2019 WASSCE Core Math Paper 1" on Brilla is **original questions authored to the 2019 paper's format, topic weighting, and difficulty blueprint** — it is not, and must never be presented as, the actual 2019 WAEC paper.

**Decision — UI labelling:** keep the year-grouped structure in `PastPapers.tsx` (it is genuinely useful: students train against a year's blueprint and format), but surface the existing content label on every pre-2023 paper view: "Original practice questions styled to the {year} paper format — not official WAEC material." The TakePaper and PaperResults screens must carry the same label. This is already the established label pattern for authored banks; no new UI component, just wiring it onto the past-paper flow.

**Landing-page implication:** the landing claim was already corrected to "Past Papers (2023–2024)". It must **not** silently become "2015–2024" — update the claim only per-phase as content ships to prod (e.g. "(2019–2024)" after Phase 3, "(2015–2024)" after Phase 4). A claim edit without the content behind it reopens the exact FICTION problem the 2026-09-06 remediation fixed.

## Risks

- **Content review bandwidth is the bottleneck, not engineering.** ~800 questions/phase through academic review is the pacing item; engineering per phase is near-zero after the generator lands. Mitigation: recruit/batch reviewers per subject; do not compress review gates to hit dates.
- **Review fatigue → quality drift** across phases. Mitigation: the acceptance checklist in §4 is mechanical; validator enforces most of it, reviewer focuses on correctness/explanation quality.
- **Misleading-year perception** if the honesty label is skipped. Mitigation: §5 label wiring is a ship gate for Phase 1, not a follow-up.
- **Migration number collision** with concurrent content workstreams. Mitigation: 402+ reserved here (372–379 school subscriptions, 380–386 flashcards, 387–401 NSMQ); re-verify `database/migrations/` before generating each phase's migration.
